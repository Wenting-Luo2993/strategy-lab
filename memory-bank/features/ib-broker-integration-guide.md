# IB Paper Trading Setup, Testing, and Usage Guide

**Status**: Phase 1 foundation available  
**Scope**: Manual configuration, smoke testing, operational metrics, and dashboard usage  
**Primary command**: `python scripts/ib_paper_smoke.py`

This guide explains how to connect the trading bot to an Interactive Brokers paper account, test market data/order/fill flow end-to-end, and view operational execution metrics.

---

## What This Supports

Current P0 flow:

1. Connect to IB TWS or IB Gateway paper account.
2. Read account summary.
3. Request market data for a stock symbol.
4. Optionally submit a small paper market order.
5. Wait for the fill event.
6. Record execution metrics locally and, optionally, to Supabase.
7. View remote metrics in the Vercel-ready dashboard.

Tracked execution metrics:

- `expected_fill_price`
- `actual_fill_price`
- `slippage`
- `slippage_bps`
- `latency_ms`
- `commission`
- `fill_quantity`

## Prerequisites

### Local Software

- Python environment with trading bot dependencies installed.
- Interactive Brokers TWS or IB Gateway installed.
- IB paper account credentials.
- For dashboard work: Node.js and npm.

### Python Dependencies

Install trading bot dependencies from the trading bot package folder:

```powershell
pip install -r vibe/trading_bot/requirements.txt
```

The IB adapter requires:

```powershell
pip install ib-insync
```

The remote Supabase metrics sink uses `aiohttp`, which is already listed in the trading bot requirements. Local SQLite metrics do not require Supabase credentials.

## Manual IB Setup

### 1. Start TWS Or IB Gateway

Log in with the IB paper trading account.

Default ports:

| App | Paper Port | Live Port |
|-----|------------|-----------|
| TWS | `7497` | `7496` |
| IB Gateway | often `4002` | often `4001` |

Use the port shown in your local IB API settings if it differs.

### 2. Enable API Access

In TWS or IB Gateway settings:

- Enable ActiveX and Socket Clients.
- Confirm the socket port matches the command/config you will use.
- Allow connections from `127.0.0.1`.
- Keep paper trading selected.

For first-time use, TWS may show an API connection confirmation dialog. Accept it for the client id you use.

### 3. Configure Environment Variables

Create or update `.env` values as needed:

```bash
BROKER_TYPE=interactive_brokers
BROKER_MODE=paper
IB_HOST=127.0.0.1
IB_PORT=7497
IB_CLIENT_ID=1
IB_ACCOUNT_ID=
IB_SMOKE_SYMBOL=AAPL
IB_SMOKE_QUANTITY=1
OPERATIONAL_METRICS_DB=./data/local/operational_metrics.db
```

`IB_ACCOUNT_ID` is optional for the smoke script. Set it if your IB session has multiple accounts.

## Operational Metrics Setup

### Local SQLite Metrics

Local metrics are enabled by default in the smoke script. The default path is:

```text
./data/local/operational_metrics.db
```

Override it with:

```powershell
python scripts/ib_paper_smoke.py --metrics-db ./data/local/operational_metrics.db
```

### Optional Supabase Remote Metrics

Use Supabase free tier for a zero-cost remote database that the dashboard can read.

Create this table in Supabase:

```sql
create table operational_metrics (
  id bigint generated by default as identity primary key,
  metric_name text not null,
  metric_value double precision not null,
  dimensions jsonb not null default '{}'::jsonb,
  timestamp timestamptz not null,
  created_at timestamptz not null default now()
);
```

Set these environment variables for remote writes:

```bash
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your-anon-key
SUPABASE_OPERATIONAL_METRICS_TABLE=operational_metrics
```

When these values are present, the smoke script records metrics locally and mirrors them to Supabase.

## Testing Guide

### 1. Validate The Smoke CLI Loads

```powershell
python scripts/ib_paper_smoke.py --help
```

Expected result: command options are printed, including `--symbol`, `--quantity`, `--submit-order`, and Supabase options.

### 2. Readonly IB Smoke Test

Use this first. It does not submit an order.

```powershell
python scripts/ib_paper_smoke.py --symbol AAPL
```

Expected flow:

- Connects to IB.
- Logs account summary.
- Requests market data.
- Prints bid, ask, last, and market price.
- Disconnects cleanly.

### 3. Paper Order Smoke Test

This submits a real paper-market order. Keep quantity small.

```powershell
python scripts/ib_paper_smoke.py --symbol AAPL --quantity 1 --submit-order
```

Expected flow:

- Connects to IB.
- Reads market data and uses it as expected fill.
- Submits a paper market order.
- Waits for fill event.
- Logs actual fill, slippage, slippage bps, and latency.
- Records metrics to SQLite and optionally Supabase.

### 4. Test With Custom IB Port Or Client ID

```powershell
python scripts/ib_paper_smoke.py --host 127.0.0.1 --port 7497 --client-id 91 --symbol AAPL
```

Use a different client id if TWS reports a duplicate client id.

### 5. Python Static Validation

```powershell
python -m py_compile `
  vibe/trading_bot/brokers/base.py `
  vibe/trading_bot/brokers/interactive_brokers.py `
  vibe/trading_bot/storage/operational_metrics.py `
  scripts/ib_paper_smoke.py `
  vibe/tests/trading_bot/test_brokers.py
```

### 6. Unit Tests

When `pytest` is installed:

```powershell
python -m pytest vibe/tests/trading_bot/test_brokers.py
```

## Dashboard Setup And Usage

Dashboard app:

```text
apps/operational-metrics-dashboard
```

### 1. Configure Dashboard Environment

Create `.env.local` in the dashboard folder:

```bash
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_ANON_KEY=your-anon-key
SUPABASE_OPERATIONAL_METRICS_TABLE=operational_metrics
```

### 2. Run Locally

```powershell
cd apps/operational-metrics-dashboard
npm install
npm run dev
```

Open:

```text
http://localhost:3000
```

### 3. Build And Lint

```powershell
cd apps/operational-metrics-dashboard
npm run build
npm run lint
```

### 4. Deploy To Vercel

Create a Vercel project using:

```text
apps/operational-metrics-dashboard
```

Add these environment variables in Vercel:

- `SUPABASE_URL`
- `SUPABASE_ANON_KEY`
- `SUPABASE_OPERATIONAL_METRICS_TABLE`

The dashboard revalidates data every 30 seconds.

### Dashboard Views

Current dashboard shows:

- total metric rows
- fill count
- average latency
- average slippage bps
- worst slippage bps
- max latency
- recent fill table
- symbol-level execution quality summary

## Daily Usage Workflow

### Before Market Open

1. Start TWS or IB Gateway.
2. Confirm paper mode.
3. Confirm API socket access is enabled.
4. Run readonly smoke test:

```powershell
python scripts/ib_paper_smoke.py --symbol AAPL
```

### During Paper Validation

Run a small paper order test when ready:

```powershell
python scripts/ib_paper_smoke.py --symbol AAPL --quantity 1 --submit-order
```

Then review:

- terminal fill output
- local SQLite operational metrics
- Supabase rows, if remote metrics are enabled
- dashboard fill and slippage summary

### After Testing

Check paper account positions in TWS/Gateway. Close any test positions manually if needed.

## Troubleshooting

### `ib_insync` Import Error

Install the dependency:

```powershell
pip install ib-insync
```

### Cannot Connect To IB

Check:

- TWS/Gateway is running.
- You are logged into the paper account.
- API socket access is enabled.
- Port matches `--port` or `IB_PORT`.
- Client id is not already in use.
- TWS accepted the API connection dialog.

### No Market Data

Possible causes:

- Market is closed and delayed data is unavailable.
- Account lacks market data permissions.
- Symbol is invalid or not qualified by IB.
- TWS/Gateway has not fully initialized after login.

Try a highly liquid stock such as `AAPL` or `MSFT` first.

### Order Does Not Fill

For market orders this is usually caused by:

- market closed
- symbol not tradeable in the account
- paper account trading restrictions
- order held or rejected by IB

Check TWS order status and the terminal error output.

### Metrics Not Appearing In Dashboard

Check:

- `SUPABASE_URL` and `SUPABASE_ANON_KEY` are set in both smoke-script and dashboard environments.
- Supabase table name matches `SUPABASE_OPERATIONAL_METRICS_TABLE`.
- Rows exist in Supabase.
- Row-level security permits read access for the anon key, or a read policy has been added.

## Safety Notes

- Keep `BROKER_MODE=paper` until live trading is explicitly approved.
- Use tiny test quantities for smoke tests.
- Confirm positions in TWS/Gateway after every paper-order test.
- Do not use the live IB port/account for smoke testing.
